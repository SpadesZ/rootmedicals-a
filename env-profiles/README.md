# Environment profiles (dev / vm)

Keeps **local development** config separate from the **VM delivery** config so
local tinkering never leaks into the hand-off build. This mirrors the client-side
`default_config.json` / `default_config.vm.json` split, but for the server stack.

## Files

| File | Tracked? | Role |
| --- | --- | --- |
| `env-profiles/dev.env` | yes | Local development values (no secrets). |
| `env-profiles/vm.env`  | yes | VM / delivery values (no secrets). `# CONFIRM` lines need VM-specific verification. |
| `../.env`              | **no** (gitignored) | The *active* file docker-compose reads. Generated by the switch script — do not hand-edit as the source of truth. |
| `../.env.topic`        | **no** (gitignored) | Cross-service `LLMEBM_TOPIC_GENERATION_TOKEN` secret. Never touched by the switch. |

Secrets (topic token, provider API keys) live in `../.env.topic` and the LAVA
settings store — **never** in these profiles.

## Switch

From the repo root:

```powershell
.\Use-Environment.ps1 -Profile dev   # local development
.\Use-Environment.ps1 -Profile vm    # VM / delivery build
.\Use-Environment.ps1                # show which profile is currently active
```

The script backs up the current `.env` to `.env.bak`, writes the chosen profile
to `.env` (UTF-8, no BOM), and leaves `.env.topic` alone. Changes take effect on
the next container recreate:

```powershell
docker compose -f llmebm\docker-compose.yml up -d --force-recreate
docker compose -f ebm-rag\docker-compose-rag.yml up -d --force-recreate
```

## What actually differs (and why)

Only values the code reads are meaningful:

- `EBM_RAG_BASE_URL` — llmebm → ebm-rag. Dev uses `host.docker.internal:33301`
  (llmebm in Docker → host ebm-rag). On a Linux VM `host.docker.internal` does
  not resolve by default — use the ebm-rag service address. (`# CONFIRM`)
- `LLMXX_LAVA_TASK_BASE_URL` / `LLMXX_RAG_BASE_URL` — llmxx-server → ebm-rag LAVA.
  Same host caveat on the VM. (`# CONFIRM`)
- `LLMXX_LAVA_TIMEOUT_SECONDS` — 2s locally (fixture/fast), 30s on VM (real
  network LLM calls).
- `LLMXX_CLIENT_DEMO_FIXTURE_ENABLED` — `true` locally, `false` for a live VM.

`ROOTMEDICALS_ENV` / `ROOTMEDICALS_HOST` are labels only (not read by code);
they make it obvious in logs which profile is live.
